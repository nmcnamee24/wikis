# Experience Principles

## 1. The Topic Owns The Screen

The app frame should disappear. Navigation should be present but quiet. The hierarchy is:

1. Pillar
2. Topic title
3. Explanation
4. Hook
5. Visual atmosphere

The topic is the hero, not the UI.

## 2. No Onboarding Required

The first session should start directly on a topic.

No account wall. No preference survey. No category picker. No permission prompts. No tutorial carousel.

If an interaction needs explanation, the design has already failed. Gestures can be learned through subtle motion, haptics, and the first few topic transitions.

## 3. One Idea At A Time

Each card teaches one thing. It should not try to cover the full topic.

Good card:

- explains the central idea
- includes one surprising angle
- leaves a natural bridge to another topic

Bad card:

- lists facts
- summarizes a whole Wikipedia entry
- stuffs in dates and names without narrative
- sounds like generic AI output

## 4. Curiosity Over Retention

The app should not use dark retention mechanics.

Avoid:

- streak pressure
- push notifications as default behavior
- artificial scarcity
- autoplay audio/video
- infinite engagement prompts
- social comparison

Prefer:

- satisfying exits
- visible learning history
- saved topics
- elegant re-entry into prior curiosity paths

## 5. Fast, Dense, Beautiful

The experience should feel premium and efficient.

Cards should load instantly or appear instant through prefetching. Typography should carry the product. Images should support the topic without making the app dependent on unreliable source media.

## 6. Trust Is A Feature

Wikis can be AI-assisted, but it cannot feel ungrounded.

Every topic should have:

- source references
- generated explanation metadata
- editorial quality checks
- safe fallbacks for weak source material
- clear rejection of uncertain claims

The user does not need to see citations on the main card, but the product needs them behind the scenes.

## 7. Progress Without Gamification Noise

The map and profile should show what the user has learned, not manipulate them into returning.

Progression should feel reflective:

- "Here is where your curiosity has taken you."

Not performative:

- "Keep your streak or lose progress."
