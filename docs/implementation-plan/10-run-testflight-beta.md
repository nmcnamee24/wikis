# Step 10: Run TestFlight Beta

## Goal

Validate the complete product with real users before public launch.

## Build

Run an internal beta first, then an external TestFlight beta.

## Tasks

1. Create Apple Developer account if needed.
2. Configure bundle ID and signing.
3. Create App Store Connect app record.
4. Upload first TestFlight build.
5. Invite internal testers.
6. Fix install, launch, crash, and layout issues.
7. Invite external beta testers.
8. Collect qualitative feedback.
9. Review analytics for first-session behavior.
10. Review topic quality reports.
11. Expand content graph based on weak paths.
12. Freeze v1 scope.

## Beta Questions

Ask:

- Did you learn something within 30 seconds?
- Did the next swipe make sense?
- Did left-swipe teleport feel fun or random?
- Did any card feel wrong, boring, or AI-generated?
- Did the map make your exploration feel meaningful?
- Would you replace a social media check with this?

## Acceptance Criteria

- Crash-free rate is launch-worthy.
- First card loads reliably.
- Users understand the core loop without onboarding.
- Testers report at least some memorable topics.
- Bad cards can be fixed quickly.
- No critical App Store compliance issues remain.

## Do Not Add During Beta

- Major new features
- Social layer
- Complex search
- Monetization
- Achievements
